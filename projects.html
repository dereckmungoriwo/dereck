Networking

Small Office Network Design & Implementation

Designed and built a segmented network for a 25-user office, with separate staff, guest and server networks.

Project overview

A small business needed a reliable, secure network where guests could not reach internal systems. I designed the topology, planned the addressing, and implemented and tested it in a simulated environment.

Objectives

  • Segment the network into separate VLANs for staff, guests and servers.
  • Plan an efficient IP addressing scheme that leaves room to grow.
  • Restrict guest access to the internet only.
  • Document the design so it can be maintained.

My role

I carried out the full design: topology, subnet plan, configuration and testing, and wrote the network documentation.

How it works

  • Addressing: A /24 block was divided with VLSM into staff (VLAN 10), guest (VLAN 20) and server (VLAN 30) subnets, sized to each group.
  • Switching and routing: Access switches carried the VLANs over trunk links to a router that handled inter-VLAN routing (router-on-a-stick).
  • Services: DHCP scopes were created per VLAN, with static addresses for servers and DNS pointing to the internal server.
  • Security: Access control lists blocked guest traffic from reaching staff and server VLANs while allowing internet access.

Tools and technologies

  • Cisco Packet Tracer
  • Cisco IOS
  • VLANs and trunking
  • Inter-VLAN routing
  • DHCP and DNS
  • ACLs
  • Wireshark

Results and lessons

All VLANs communicated as designed, and the guest network was fully isolated. I learned to plan addressing before touching a device, and to test every rule from both sides.

Cloud

Cloud Website Hosting & Deployment

Hosted a website on a cloud platform with HTTPS, a content delivery network and automated deployment.

Project overview

I wanted a fast, secure and low-cost way to host a website, and to automate updates so changes go live without manual uploads.

Objectives

  • Host the site on cloud storage with a custom domain and HTTPS.
  • Serve content globally through a CDN for speed.
  • Automate deployment from a code repository.
  • Keep access secure and costs low.

My role

I designed the architecture, configured the cloud services and DNS, and built the deployment pipeline.

How it works

  • Hosting: Static files were stored in a cloud storage bucket and served through a CDN with an SSL/TLS certificate.
  • DNS: The custom domain pointed to the CDN through DNS records.
  • Security: A least-privilege identity and access policy limited what the deployment account could do.
  • Automation: A pipeline pushed changes from the repository to the bucket and cleared the CDN cache on each release.

  • Cloud storage
  • CDN
  • DNS
  • SSL/TLS
  • IAM
  • Git and CI/CD

Results and lessons

Deployments went from manual uploads to a single push, and page loads improved noticeably. I learned the value of least-privilege access and of monitoring cost from day one.

Networking

Site-to-Site VPN & Network Monitoring Lab

Connected two branch networks with an encrypted VPN and set up monitoring to track network health.

Project overview

Two branch offices needed to share resources securely over the internet, and the network team needed visibility into performance and faults.

Objectives

  • Create an encrypted tunnel between two sites.
  • Enable routing so both networks can reach each other.
  • Monitor device status, bandwidth and logs.
  • Test failure scenarios and recovery.

My role

I built the lab, configured the VPN and routing, and set up the monitoring and alerting.

How it works

  • VPN: An IPsec tunnel was configured between the two edge routers with agreed encryption and authentication settings.
  • Routing: A dynamic routing protocol (OSPF) advertised each site's networks across the tunnel.
  • Monitoring: SNMP polling and syslog collection fed a monitoring dashboard showing uptime, bandwidth and alerts.
  • Testing: I simulated a link failure and confirmed that alerts fired and traffic recovered.

Tools and technologies

  • IPsec VPN
  • OSPF
  • SNMP
  • Syslog
  • Zabbix or PRTG (add yours)
  • Linux
  • Troubleshooting

Results and lessons

Both sites communicated securely and alerts arrived within a minute of a fault. I learned how much of networking is methodical troubleshooting, one layer at a time.

Cloud

Cloud Virtual Network & Server Deployment

Built a private virtual network in the cloud with public and private subnets and a hardened server.

Project overview

I set out to understand how real cloud environments are structured, and to deploy a server that follows security best practice.

Objectives

  • Create an isolated virtual network with public and private subnets.
  • Deploy a Linux server and control access with firewall rules.
  • Back up data and recover it successfully.
  • Track usage and costs.

My role

I designed the network, deployed and secured the server, and tested backup and recovery.

How it works

  • Network: A virtual private cloud was split into a public subnet (web tier) and a private subnet (application and data tier).
  • Access: Security groups allowed only the required ports, with administrative access through a secured jump host and key-based login.
  • Outbound traffic: A NAT gateway let private servers reach updates without being exposed to the internet.
  • Resilience: Scheduled snapshots backed up data, and I restored a snapshot to prove recovery worked.

Tools and technologies

  • AWS or Azure (add yours)
  • Virtual private cloud
  • Security groups
  • Linux administration
  • SSH key authentication
  • Snapshots and backups
  • Cost monitoring

Results and lessons

The environment was secure by design and recoverable on demand. I learned how cloud networking maps onto traditional networking concepts.
